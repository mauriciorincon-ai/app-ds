# ADR 019 — Own UI primitives instead of shadcn/ui

- **Status:** accepted
- **Date:** 2026-10-06
- **Sprint:** 007 «Agrupar y multiclase» (audit finding AU-S7-25; constitution audit AC-4)
- **Records:** a decision taken in Sprint 001 and never written down

## Context

The constitution (`CLAUDE.md`, «Stack») and `design-system.md` said the interface is built with
«Tailwind + shadcn/ui», customised with the app's tokens. shadcn/ui was never installed. Sprint 001
deferred it (friction K2 of its log: «shadcn/ui NO instalado pese a estar en el stack», moved to the
design phase), and that phase built the primitives by hand in `src/components/ui.tsx` instead. Since
then every screen uses those primitives, and no ADR said why. The Sprint 007 constitution audit
(AC-4) and the sprint audit (AU-S7-25) flagged the gap: a reader of the stack line would look for a
`components.json`, Radix packages and generated components that do not exist.

What the app needs from its primitives is small and fixed by the design system:

- `Button` with three variants (`primary`, `secondary`, `ghost`), 44 px tall, and a stroke icon to the
  left of the text on every action button (the user's rule since the S4 star gate);
- `Card`, `Badge` and `MetricTile`;
- `Icon`: a closed set of inline stroke SVGs (`IconName`), `currentColor`, `aria-hidden`, no emoji.

The only complex widget, the model sheet (E3), is a native `<dialog>` opened with `showModal()`: the
browser gives focus trapping, Escape and an inert background (`FichaModelo.tsx`).

## Decision

1. **The primitives are the app's own,** in `src/components/ui.tsx`, styled only with the tokens of
   `design-system.md`. No shadcn/ui, no Radix, no `class-variance-authority`, `clsx` or
   `tailwind-merge`.
2. **Dialogs use the native `<dialog>`.** If a future widget needs behaviour the platform does not
   give (a combobox, a menu with roving focus), that widget gets its own ADR before a library enters.
3. **`design-system.md` says «primitivos propios»** and cites this ADR. The stack line of `CLAUDE.md`
   is regenerated by the planning house, so this app does not edit it: the drift is reported under
   deviation D8 of the Sprint 007 log, with the other stale statements of the constitution.

## Consequences

- No dependency, no generated code and no upstream style to override: the landing script budget
  (ADR 018) pays only for the few primitives the app draws.
- The design system is the only source of style. A new variant is a deliberate edit of `ui.tsx` and
  `design-system.md`, not a regenerated file.
- Accessibility is the app's job, not a library's: the 44 px targets, the focus ring, the icon rule and
  the dialog behaviour live in `ui.tsx` and `design-system.md`. The e2e suite runs axe in both
  themes on every screen it touches, and the capture scripts' interaction pass activates each
  control (rule 17).
- The kit's `diseno-ui` skill still speaks of «shadcn/ui personalizados». For this app, read it as «the
  app's own primitives»; the wording belongs to the kit and travels to the planning house with D8.
